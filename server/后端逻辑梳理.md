# 后端从 0 到现在的逻辑梳理

## 一、整体架构概览

```
server/
├── index.js          # 入口：Express 应用、中间件、路由挂载、监听端口
├── package.json      # 依赖与启动脚本
├── .env / .env.example  # 环境变量（密钥、数据库地址）
├── config/
│   └── passport.js   # JWT 认证策略配置
├── models/
│   ├── index.js      # 统一导出 User、Course
│   ├── user-model.js # 用户模型（密码哈希、角色、comparePassword）
│   └── course-model.js # 课程模型（讲师、学生列表）
├── routes/
│   ├── index.js      # 统一导出 auth、course 路由
│   ├── auth.js       # 注册、登录（无 JWT 保护）
│   └── course-route.js # 课程 CRUD、选课（全部 JWT 保护）
└── validation.js    # Joi 校验：注册、登录、课程
```

**请求流向**：  
HTTP 请求 → Express 中间件（JSON 解析、CORS）→ 路由匹配 → 若为 `/api/courses` 先过 `passport.authenticate('jwt')` → 进入具体路由处理 → 读/写 MongoDB → `res.send` 返回。

---

## 二、从 0 开始的搭建顺序（逻辑时间线）

### 1. 项目初始化

- 在 `server/` 下执行 `npm init`，得到 `package.json`。
- 安装核心依赖：
  - **express**：Web 框架，处理 HTTP 请求与路由。
  - **mongoose**：连接 MongoDB，定义 Schema、做 CRUD。
  - **dotenv**：从 `.env` 读取环境变量。
  - **cors**：允许前端（如 localhost:3000）跨域访问后端（如 8080）。

**入口**：`package.json` 里 `"start": "node index.js"`，所以真正跑起来的是 `index.js`。

---

### 2. 入口文件 index.js：把“服务器”搭起来

**作用**：创建 Express 应用、连数据库、挂中间件、挂路由、监听端口。

| 步骤 | 代码/逻辑 | 说明 |
|------|-----------|------|
| 加载环境变量 | `dotenv.config()` | 把 `.env` 里的 `PASSPORT_SECRET`、`MONGO_URI` 等注入 `process.env` |
| 连接数据库 | `mongoose.connect(MONGO_URI)` | 默认 `mongodb://127.0.0.1:27017/mernDB`，可用环境变量覆盖 |
| 全局中间件 | `express.json()`、`express.urlencoded({ extended: true })` | 解析请求体为 JSON 或表单，便于在路由里用 `req.body` |
| 跨域 | `app.use(cors())` | 允许前端跨域请求 |
| 挂载认证策略 | `require('./config/passport')(passport)` | 注册 JWT 策略，供后面 `passport.authenticate('jwt')` 使用 |
| 挂载路由 | `app.use("/api/user", authRoute)` | 所有 `/api/user/*` 走 `routes/auth.js` |
| 挂载受保护路由 | `app.use("/api/courses", passport.authenticate('jwt', { session: false }), courseRoute)` | 先验 JWT，再进 `routes/course-route.js` |
| 启动监听 | `app.listen(8080, ...)` | 服务跑在 8080 端口 |

**要点**：  
- `/api/user` 不验 JWT，用来注册、登录。  
- `/api/courses` 下每一个请求都会先经过 `passport.authenticate('jwt')`，通过后 `req.user` 才有值。

---

### 3. 数据层：models

#### 3.1 models/index.js

- 只做聚合导出：`{ User, Course }`。
- 其他文件通过 `require('../models')` 拿到两个模型。

#### 3.2 user-model.js（用户）

- **Schema 字段**：  
  `username`（必填，3–50）、`email`（必填，6–50）、`password`（必填）、`role`（枚举 `student` / `instructor`）、`date`（默认 `Date.now`）。
- **pre('save') 钩子**：  
  在保存前，若是新用户或密码被修改，用 `bcrypt.hash(this.password, 10)` 把明文密码哈希后存库。
- **实例方法**：  
  - `isStudent()`、`isInstructor()`：根据 `role` 判断身份。  
  - `comparePassword(plainPassword)`：用 `bcrypt.compare` 和库里的哈希比对，返回布尔值。

**用途**：注册时自动哈希密码；登录时用 `comparePassword` 校验；课程路由里用 `req.user.isStudent()` 等做权限判断。

#### 3.3 course-model.js（课程）

- **Schema 字段**：  
  `title`、`description`、`price`（必填）、`instructor`（ObjectId，ref: 'User'）、`students`（数组，默认 []）。
- **用途**：  
  一门课对应一个讲师（`instructor`），多门课可被多个学生选（`students` 里存学生 ID）。  
  路由里用 `populate("instructor", ["username", "email"])` 把讲师信息带出来。

---

### 4. 校验层：validation.js

用 **Joi** 定义三套校验函数，供路由在写库前调用：

| 函数 | 用途 | 规则概要 |
|------|------|----------|
| `registerValidation(data)` | 注册 | username 3–50、email 合法、password 6–255、role 为 student/instructor |
| `loginValidation(data)` | 登录 | email 合法、password 6–255 |
| `courseValidation(data)` | 课程创建/更新 | title 6–50、description 6–50、price 数字 10–9999 |

返回格式：`{ error, value }`。若 `error` 存在，路由里通常 `return res.status(400).send(error.details[0].message)`。

---

### 5. 认证层：config/passport.js

**作用**：告诉 Passport 如何从请求里拿 JWT、如何验证、验证成功后把谁放进 `req.user`。

- **从哪里拿 Token**：  
  `ExtractJwt.fromAuthHeaderWithScheme("jwt")` → 从请求头 `Authorization: jwt <token>` 里取。
- **用什么验签**：  
  `process.env.PASSPORT_SECRET`，须与登录签发 token 时用的密钥一致。
- **验证流程**：  
  1. 解出 payload（如 `_id`、`email`）。  
  2. 用 `_id` 调 `User.findOne({ _id: jwt_payload._id })`。  
  3. 若找到用户 → `done(null, foundUser)`，Passport 会把 `foundUser` 挂到 `req.user`。  
  4. 若未找到或出错 → `done(null, false)` 或 `done(e, false)`，请求被拒（401/500）。

**结果**：所有经过 `passport.authenticate('jwt', { session: false })` 的路由，都能安全使用 `req.user`。

---

### 6. 路由层：routes

#### 6.1 routes/index.js

- 只做导出：`{ auth: require('./auth'), course: require('./course-route') }`。  
- `index.js` 里通过 `require("./routes").auth` 和 `.course` 拿到两个 router。

#### 6.2 routes/auth.js（前缀 /api/user）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /testAPI | 简单测试，返回 "auth test Success" |
| POST | /register | 注册：Joi 校验 → 查 email 是否已存在 → 新建 User（save 时自动哈希密码）→ 返回成功信息 |
| POST | /login | 登录：Joi 校验 → 按 email 查用户 → comparePassword → 成功则 `jwt.sign({ _id, email }, PASSPORT_SECRET, { expiresIn: '7d' })`，返回 `{ msg, token: "JWT " + token, user }` |

**注意**：登录返回的 token 带 `"JWT "` 前缀，前端需要把整个字符串放进 `Authorization` 头，passport 用 scheme `"jwt"` 解析。

#### 6.3 routes/course-route.js（前缀 /api/courses，全部带 JWT）

**前提**：请求已通过 `passport.authenticate('jwt')`，故每个 handler 里都有 `req.user`。

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | / | 查所有课程，populate instructor |
| GET | /instructor/:_instructor_id | 按讲师 ID 查其开的课 |
| GET | /student/:_student_id | 按学生 ID 查其选的课（students 数组包含该 ID 的课程） |
| GET | /findByName/:name | 按课程标题查 |
| GET | /:_id | 按课程 ID 查单门课 |
| POST | / | 新增课程：courseValidation → 若 `req.user.isStudent()` 则 400 → 用 `req.user._id` 作为 instructor 创建 Course |
| POST | /enroll/:_id | 选课：找到课程，把 `req.user._id` push 进 `course.students` 再 save |
| PATCH | /:_id | 更新课程：courseValidation → 确认课程存在且 `courseFound.instructor.equals(req.user._id)` → 仅讲师可更新 |
| DELETE | /:_id | 删除课程：确认课程存在且讲师本人 → 仅讲师可删 |

**权限逻辑**：  
- 发课、改课、删课：只允许讲师，且改/删必须是该课程的 `instructor`。  
- 选课：任意登录用户都可调用，业务上通常由前端限制为学生。

## 三、两条主流程串起来

### 1. 注册 → 登录 → 拿到 JWT

1. 前端 POST `/api/user/register`，body 含 username、email、password、role。  
2. auth 路由：registerValidation → User 查重 email → `new User(...).save()`（pre-save 哈希密码）→ 返回成功。  
3. 前端 POST `/api/user/login`，body 含 email、password。  
4. auth 路由：loginValidation → User.findOne({ email }) → `foundUser.comparePassword(password)` → 成功则签发 JWT，返回 `{ msg, token, user }`。  
5. 前端把 token（如 "JWT xxx"）存起来，之后请求课程接口时在 Header 里带 `Authorization: <该 token>`。

### 2. 带 JWT 访问课程接口

1. 前端请求任意 `/api/courses/...`，Header 带 `Authorization: jwt <token>`。  
2. Express 先走 `passport.authenticate('jwt')`：  
   - 从 Header 取 token → 用 PASSPORT_SECRET 验签 → 用 payload._id 查 User → 把用户挂到 `req.user`。  
3. 再进入 course-route 里对应的 handler：  
   - 用 `req.user` 判断身份（isStudent/isInstructor）、取 `req.user._id` 作为讲师或学生 ID，进行查库/写库。  
4. 最后 `res.send(...)` 把结果返回给前端。

## 四、环境变量与运行

- **.env（不提交 git）**：  
  - `PASSPORT_SECRET`：JWT 签发与验证用的密钥。  
  - 可选：`MONGO_URI`，不写则用默认 `mongodb://127.0.0.1:27017/mernDB`。
- **.env.example**：  
  只写变量名和示例值，方便别人本地新建 `.env`。

**启动**：  
在 `server/` 下执行 `npm start`（即 `node index.js`），需保证 MongoDB 已运行，且 `.env` 里 PASSPORT_SECRET 已配置。

## 五、小结表

| 层次 | 文件 | 职责 |
|------|------|------|
| 入口 | index.js | 创建 app、连 DB、挂中间件与路由、listen(8080) |
| 环境 | .env / dotenv | 提供 PASSPORT_SECRET、MONGO_URI |
| 模型 | models/*.js | User（含密码哈希与 comparePassword）、Course（讲师+学生列表） |
| 校验 | validation.js | 注册、登录、课程 body 的 Joi 规则 |
| 认证 | config/passport.js | JWT 提取、验签、查用户、写 req.user |
| 路由 | routes/auth.js | 注册、登录（无 JWT） |
| 路由 | routes/course-route.js | 课程 CRUD、选课（全需 JWT，且用 req.user 做权限） |

整体上，后端从 0 到现在的逻辑就是：**Express 提供 API，Mongoose 操作 MongoDB，Joi 校验输入，Passport-JWT 保护课程相关接口，并在课程路由里用 req.user 做角色与权限判断。**
